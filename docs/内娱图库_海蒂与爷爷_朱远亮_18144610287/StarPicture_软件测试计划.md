## 五、简介

### 5.1 系统概述

- **项目编号**：StarPicture-2026-001
- **项目名称**：内娱图库（StarPicture）
- **项目简介**：基于 Spring Boot 2.7.6 + MyBatis-Plus + MySQL 8 + 腾讯云 COS 构建的图片管理与分享平台。前端通过 Knife4j 暴露 REST 接口，提供用户管理、头像管理、图片上传/编辑/搜索、AI 扩图、空间协作等完整功能。本次测试覆盖 **user、picture、space、头像 + 获取当前用户** 四大核心模块。

### 5.2 编写目的

本文档是 StarPicture 项目测试活动的纲领性文件，明确本次测试的范围、策略、资源、进度与进入/通过/终止准则，是后续《软件测试说明》《软件测试用例》和《软件测试报告》编写的依据。

### 5.4 术语说明

| 术语 | 解释 |
|---|---|
| 黑盒测试 | 功能测试，检查程序是否能适当地接收输入并产生正确的输出 |
| 等价类划分法 | 把输入域划分成若干部分，从每个部分中选取代表性数据作为测试用例 |
| 边界值分析法 | 通过选择等价类边界的测试用例进行测试 |
| 错误推测法 | 基于经验和直觉推测程序中可能存在的各种错误 |
| 场景法 | 模拟特定场景和条件边界发生的事情 |
| 回归测试 | 验证已修改问题，并验证是否引入新的缺陷 |
| 缺陷修复率 | 已修复缺陷数 / 缺陷总数 × 100% |
| COS | 腾讯云对象存储（Cloud Object Storage） |
| AI 扩图 | 基于阿里云百炼 outPainting 接口的图片尺寸扩展 |

## 八、测试范围及测试点

### 8.1 测试模块分配

| 模块 | 测试人员 | 2 个核心功能点 | 主要 API |
|---|---|---|---|
| user | 朱远亮 | 用户注册 + 用户登录 | /user/register、/user/login |
| picture | 李冠燃 | 图片本地上传 + 关键字搜索 | /file/upload、/picture/search/picture |
| space | 李坤纬 | 空间创建 + 空间成员管理 | /space/add、/spaceUser/* |
| 头像 + 获取当前用户 | 林景彬 | 头像上传 + 获取当前用户 | /file/upload/avatar、/user/get/login |

### 8.2 测试点（按模块）

#### 8.2.1 user 模块（朱远亮）

- 用户注册：账号密码正确/已存在/密码不一致/账号为空/账号长度不足
- 用户登录：账号密码正确/密码错误/账号不存在/空 body/密码小于8字符
- 性能：登录 50 并发（JMeter）
- 接口：注册 Content-Type 错误
- 安全：登录 SQL 注入（BurpSuite）

#### 8.2.2 picture 模块（李冠燃）

- 图片本地上传：jpg/png/超2MB/非图片/空文件
- 关键字搜索：有结果/无结果/空文本/超长/未登录
- 性能：上传 20 并发
- 接口：上传缺 multipart 边界
- 安全：伪 PHP 木马上传

#### 8.2.3 space 模块（李坤纬）

- 空间创建：获取等级/创建/名称空/名称超长/未登录
- 空间成员管理：添加/查询/重复/未登录/删除
- 性能：空间分析 20 并发
- 接口：创建空间缺 Content-Type
- 安全：空间名称 XSS

#### 8.2.4 头像 + 获取当前用户 模块（林景彬）

- 头像上传：jpg/png/超2MB/非图片/空文件
- 获取当前用户：已登录/未登录/Cookie过期/Cookie伪造/头像URL正确
- 性能：文件上传 50 并发
- 接口：上传缺 multipart 边界
- 安全：伪 PHP 木马上传

### 8.3 兼容性、安全性测试

- **兼容性**：浏览器（Chrome 125+、Edge 125+、Firefox 126+），文件格式（jpg/png/webp/gif/bmp）
- **安全性**：越权访问、未登录访问、SQL 注入、XSS、文件上传漏洞、SSRF

## 十、测试执行与结果评估

### 10.1 测试进入准则

1. 测试计划已通过评审
2. 测试环境已搭建并通过冒烟测试
3. 测试用例已编写并通过同行评审
4. 缺陷跟踪表已就绪
5. 被测代码已合入 master 并打 V2.00 tag

### 10.2 测试通过准则

1. 所有 P0 用例 100% 通过
2. 致命（Severity 1）缺陷：0 个
3. 严重（Severity 2）缺陷：≤ 1 个，且已修复并回归
4. 一般（Severity 3）缺陷：≤ 总用例数的 5%
5. 关键功能流程（登录→上传→编辑→查询→删除）全部跑通
6. 性能指标：登录 P95 < 500ms，上传 2MB P95 < 3s

### 10.3 测试终止条件

1. 所有用例执行完毕，达到通过准则
2. 出现阻塞性缺陷短期无法修复
3. 需求发生重大变更
4. 超过截止时间
