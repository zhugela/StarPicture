# 软件测试演示指南（给老师看的）

> 4 人轮流演示，每人约 5-8 分钟，总时长约 30 分钟。
> **每个成员**：展示自己的用例文件 → 跑 1-2 条真实接口 → 展示截图/报告

---

## 一、演示前准备（朱远亮统一搞定）

1. **后端必须已经起来**：`http://localhost:8123/api/doc.html` 能打开
2. **每人的文件夹**里有：
   - `软件测试测试用例.xlsx`（13 条用例）
   - `功能测试/` 里有真实截图（每条用例 1 张 Postman 截图）
   - `性能测试/` 里有 JMeter Summary Report 截图
   - `接口测试/` 里有 1 张 Postman 接口测试截图
   - `安全测试/` 里有 PDF + .scan 文件
3. **把 4 人的截图文件夹提前复制到 U 盘**（防止演示时网络/本地出问题）

---

## 二、朱远亮演示（约 8 分钟）

### 第一步：展示测试计划（2 分钟）

1. 打开 `StarPicture_软件测试计划.md`（或 .docx）
2. **指着屏幕说**：
   > "这是我们的测试计划，CS001 文档。我们 4 个人分工：我负责 user 模块，李冠燃负责 picture，李坤纬负责 space，林景彬负责头像+获取当前用户。每人 13 条用例，4 种测试类型，共 52 条。"
3. **点到分工表**：让老师看到学号和姓名

### 第二步：展示我的用例 xlsx（2 分钟）

1. 打开 `软件测试测试用例.xlsx`
2. **筛选**"用例类型"列 → 选"功能测试" → 展示 10 条用例
3. **再说**：
   > "我的 2 个功能点是用户注册和用户登录，每个功能点 5 条用例。我用 Postman 逐条跑，每条都截了图。"
4. **切到性能测试**：展示 1 条（登录 50 并发）

### 第三步：现场跑 1 条接口（2 分钟）

1. 打开 Postman（**提前导入好** `user_functional.postman_collection.json`）
2. 找到 `TC-UR-001_注册_账号密码正确`
3. 点 **Send**
4. **让老师看到**：Status 200 OK、code=0、userId > 0
5. **截图**（如果现场没截，用之前的截图展示）

### 第四步：展示截图 + 报告（2 分钟）

1. 打开 `功能测试/` 文件夹 → 逐张展示关键截图（注册成功、登录失败、SQL 注入被拒）
2. 打开 `性能测试/summary_report_登录50并发.png` → 指着 Average 和 Error% 说结果
3. 打开 `安全测试/用户模块-安全报告.pdf` → 展示第 7 节"测试结论"（有条件通过）

## 九、安全测试怎么演示（重要）

**老师一般不要求现场跑 BurpSuite 攻击**（那要 5-10 分钟，老师也看不太懂）。**用"三步法"演示 5 分钟搞定**：

### 第一步：展示用例（30 秒）

1. 打开 `软件测试测试用例.xlsx`
2. **筛选"安全测试"** → 展示自己的 1 条
3. **指着说**："我的安全测试用例是 1 条 SQL 注入 / 木马上传 / XSS。"

### 第二步：展示结论（1 分钟）

打开 `安全测试/xxx模块-安全报告.pdf`，**直接翻到第 6 节"测试结果详情"**：

> "SEC-001 SQL 注入测试，在登录 username 输入 `' OR 1=1 --`，后端返回 code=40001，未绕过认证。"

> "SEC-002 越权访问测试，用 testuser01 普通用户调用管理员接口，返回 code=40300，权限校验生效。"

> "整体评价：有条件通过（高危 0 个，中危 X 个，低危 X 个，建议 X 个）"

### 第三步：展示证据（2 分钟）

**展示 2 个东西**：

1. **`xxx模块.scan` 文件**（BurpSuite 扫描导出）
   - **说**："这是我们用 BurpSuite 扫描后端接口导出的扫描结果"
   - 打开方式：右键 → 记事本打开 → 让老师看到里面有扫描数据
2. **安全测试截图**（Postman 跑 SQL 注入的截图）
   - **展示截图**：username 填 `' OR 1=1 --`、password 填 `123456`、Response code=40001

### 第四步：现场快速演示（1 分钟，可选）

如果老师想看"现场跑"，**最快的方法**是 Postman 跑：

1. Postman 打开 → 选接口测试集合
2. 找 `TC-SEC-001_登录_SQL注入`
3. **不打开 BurpSuite**，**直接 Send**
4. 展示 Response：code=40001
5. **说**："这说明后端对 SQL 注入做了防护。"

> **不需要现场演示 BurpSuite 拦截过程**（老师也不一定看得懂）。

## 十、4 个成员演示安全测试的具体话术

### 朱远亮（用户模块安全）
> "我测了 SQL 注入、越权访问、Cookie 伪造。打开报告第 6 节...SQL 注入用 `' OR 1=1 --` 后端拒绝，code=40001。越权用普通用户调用 /user/list/page/vo 返回 40300。整体评价：有条件通过。"

### 李冠燃（图片模块安全）
> "我测了伪 PHP 木马上传。打开报告...1.jpg 内容是 PHP 木马但文件名是 jpg，**后端用文件头校验**拒绝，code=40001。这说明我们不是只看扩展名，是看二进制头。"

### 李坤纬（空间模块安全）
> "我测了空间名称 XSS。打开报告...spaceName 输入 `<script>alert(1)</script>`，后端接收后渲染时被转义，XSS 防护生效。"

### 林景彬（文件模块安全）
> "我测了双扩展名绕过。打开报告...文件 `1.jpg.php`（实际是 PHP），**后端深度检测**拒绝，code=40001。MIME 类型绕过也被防住了。"
